## Process note

The spec's Assumptions say `truncateCommit` reaches the unreadable-diff state. It does not: a truncated commit object breaks `git merge-base` first, and the pack lands in the already-named no-base state (checked by hand on 2026-10-15 on the reproduction repository: `diff base ''`, the missing-base `WARNING` and two `UNGRADED` lines). `truncateBlob` naming a **directory** path reaches it: `rev-parse HEAD:<dir>` resolves to a tree object, and truncating the subtree the branch changed makes `git diff --name-only <base> HEAD` exit 128 while the base is still computed. The plan says so; the approved spec is not edited (the Assumptions line is non-binding and an amendment would need the owner's record).

### Limits stated (and in the code comments)

- **A partial list cannot be shown by a fixture.** The plan expected git to print rows and then fail. It does not: git builds the whole tree diff before it prints (a branch changing a readable `a/` and an unreadable `z/` printed no row on the parent: `0 changed file(s)`). The discard in `Read-DiffLines` is a defensive property, guarded by no fixture; a `fail-lite-partial-list` case was written, found indistinguishable from `fail`, and removed. FR-008 is therefore a stated property, not a proved one.
- **Calling `LiteAndAbuse` on the empty list is invisible.** The check is silent on an empty list, so the arm that does not call it (plan D6) is documentation, not behaviour a fixture can see.
