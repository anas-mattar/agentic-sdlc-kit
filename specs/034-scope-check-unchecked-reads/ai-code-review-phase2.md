## Findings

### F1 — A third state moves from UNGRADED/exit 0 to ERROR/exit 1 and the note names only two; the `rev-parse` form of the text is not quoted — DOC DRIFT

The note ("What an owner may newly see") says that "two states that are not 'readable' in git's sense also move: an unborn `HEAD` with an `origin/main` present, and a trunk ref that names a tag of a tree". Both are true. A third is not listed: a root git cannot open as a repository at all (not a repository, or git refusing the directory, for example the `safe.directory` refusal). There `git rev-parse --verify --quiet origin/main` exits 128, not 1, so `Get-DiffBase` records `git rev-parse of origin/main failed with exit 128` and the run ends `scope-check: ERROR could not read the merge base with main (git rev-parse of origin/main failed with exit 128), so nothing on the branch was graded - the object store may be damaged: run git fsck.`, exit 1. Reproduced: `scope-check.ps1 -All -Root <a directory with no .git> -Branch 001-thing` and `GIT_DIR=/nonexistent/.git scope-check.ps1 -All ...`: the script of `07b7ed1` prints `UNGRADED could not resolve a merge base with main - nothing checked`, exit 0; the script as it stands prints the `ERROR` above, exit 1. Plan P8 states the principle (any non-zero exit that is not "none" is "could not read") and the code is right, but "what an owner may newly see" is the section an adopter's CI owner reads, and the note's own "What it does now" quotes only the `git merge-base failed` form of the parenthesis. The `git rev-parse of <ref> failed` form (`scope-check.ps1:99`, `scope-lib.ps1:211`) and the `git fsck` hint that does not fit a missing repository are not mentioned, so an adopter who meets them has no sentence to match.
*Action: implementer adds one clause to "What an owner may newly see" naming the state (git cannot open the repository: not a repository, or a refusal such as `safe.directory`) and quoting the `git rev-parse of <ref> failed with exit <n>` form beside the `git merge-base` one, in a follow-up commit inside the Phase 2 Territory (`adoption/updating.md`). No code change: P8 covers it.*
