## Findings

### F1 — The prefix-binding limit is stated for every description; it holds only for unquoted words — DOC DRIFT

`docs/sdlc/team-workflow.md:178-180`, `adoption/updating.md:1567` (limit 6), the GAP-024 row and the decisions-log entry (`docs/roadmap.md:53`, `:718`), and `notes.md` say that a feature description "that contains a dash-led word such as `-A`, `-As`, `-R` or `-Row` is taken as a parameter, and one that ends in it fails". Reproduced on a stub with the real parameter block: that happens when the words are passed unquoted (`claim-feature.ps1 -ShortName x Add -A flag`). The documented form is `"<description>"`, one quoted argument, and then `"Add -A flag handling"`, `"Handle the -As"` and `"-As foo bar"` all bind as the description; only a description that is exactly a parameter prefix (`"-A"`, `"-R"`) fails. The unquoted case already mis-bound `-S`, `-J`, `-N` and the common parameters before this feature. So FR-011's "byte-identical without `-Row`" is true for the documented call and for every call that did not already rely on unquoted dash-led words. The phase 3 review (F1) made the same unqualified claim; phase 4 copied it into three documents and the roadmap, and the open owner decision ("reword FR-011 as an amendment") is recorded on that premise. The advice "write descriptions without dash-led words" is harmless but is the wrong repair: quote the description.
*Action: implementer, in a docs follow-up: restate the limit as "passed unquoted, or a quoted description that is itself `-A`/`-As`/`-R`/`-Row`-shaped", say that the documented quoted form is unaffected, and reword the owner decision in `notes.md` and the log entry (it may no longer need an FR-011 amendment). Not blocking.*

### F2 — The flow-down note calls `specs/_templates/roadmap-template.md` "surgical, never applied for you"; the manifest says verbatim — DOC DRIFT

`adoption/updating.md:1561`. `kit-manifest.json` classifies `specs/_templates/**` as `verbatim`, so `update-kit.ps1` will overwrite an adopted project's copy of the template with the new `Repos` paragraph. It also leaves `specs/_templates/roadmap-template.md` out of the verbatim list that an owner will compare with the update's diff.
*Action: implementer: move the template into the verbatim list and say that the adopter's own `docs/roadmap.md` is not changed. Not blocking.*
